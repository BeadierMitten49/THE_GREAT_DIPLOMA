## 2. Принципы работы со Streamlit

### Что делаем
- **Точно повторяем дизайн** из HTML-прототипов — цвета, отступы, иерархию элементов
- **Используем `st.markdown` + inline CSS** для кастомного стилизации там, где Streamlit не даёт нужный компонент
- **Разбиваем сложные страницы** на функции внутри файла (`render_sidebar()`, `render_card()` и т.д.)
- **Работаем через `api_client.py`** — вся работа с данными только через него, никаких прямых обращений к БД или use cases
- **Состояния страницы** храним в `st.session_state`
- **Пустые состояния** (empty states) реализуем для каждого блока данных
- **Состояния ошибок** показываем пользователю в понятном виде

### Чего не делаем
- **Не бизнес-логика в Streamlit** — только отображение и вызов API
- **Не добавляем функциональность** сверх того, что есть в HTML-прототипе
- **Не рефакторим** код вне текущей страницы
- **Не изменяем** `api_client.py` без явного запроса

## 4. Работа с HTML-прототипами

### Как читать HTML-файл
Каждый HTML содержит несколько **фреймов** (состояний страницы), помеченных классом `.frame-label` или `.wf-tag`. Например:
- `SCR-006 / Default` — базовое состояние
- `SCR-006 / Loading` — загрузка данных
- `SCR-006 / Empty` — данных нет
- `SCR-006 / Error` — ошибка загрузки
- `SCR-006 / Drawer-open` — открыта боковая панель детали

Все эти состояния нужно реализовать в Streamlit.

Опасность:         #B91C1C / #DC2626

## 5. Навигация и роли

Навигация зависит от роли пользователя. Сайдбар разный:

| Роль | Пункты меню |
|------|-------------|
| Директор | Главная, Заказы, Производственные задачи, Доставки, Отгрузки/Сборка, Склады (Сырьё/Упаковка/Продукция), Отчёты, Настройки |
| Производство | Главная, Производственные задачи |
| Склад | Главная, Заказы (просмотр), Отгрузки/Сборка, Склады (Сырьё/Упаковка/Продукция) |
| Доставка | Главная, Доставки |

## 6. Порядок работы (по страницам)

За один сеанс работаем **только с одной страницей**. Порядок:

1. Читаем HTML-файл для страницы
2. Создаём `docs/streamlit-redesign/pages/SCR-XXX-<name>.md` — документ задания
3. Согласовываем с пользователем
4. Реализуем
5. Отмечаем в `PROGRESS.md`

---

## 7. Что всегда проверять перед коммитом

- [ ] Страница отображается без ошибок при запуске Streamlit
- [ ] Реализованы все состояния из HTML-прототипа (Default, Empty, Error, Loading если применимо)
- [ ] Пустые состояния показывают понятный текст, а не пустой экран
- [ ] Обращения к API обёрнуты в try/except с понятным сообщением об ошибке
- [ ] Нет хардкода данных — всё приходит из API

---

## 8. Связь с архитектурой проекта

Streamlit — это `presentation/` слой. Он:
- Вызывает только `api_client.py`
- Не импортирует ничего из `domain/`, `application/`, `infrastructure/`
- Не создаёт репозитории, не вызывает use cases напрямую
